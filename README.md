## Executive Summary

本项目是一份**完整的数据分析作品集**，模拟真实电商场景下的转化率优化（CRO）全流程。选型决策、分析方法论、业务洞察和策略建议均有据可查。

**一句话总结**：发现了电商漏斗的核心瓶颈（详情页→购物车转化率仅 25.81%），量化年损失 933 万元，并给出了分优先级的、附带 ROI 估算的可执行优化方案。

严格路径下仅 73 个会话走完 Home→Checkout 全程（0.02%），95.8% 的 PDP 流量来自非标准路径。这正是为什么单一漏斗不够用。

五个渠道中四个的核心瓶颈都落在详情页→购物车，但 Direct 渠道在购物车→结算页也有明显断裂——需要差异化策略。

从 2021 年的 ~17% 降至 2023 年的 ~8%，降幅超过 50%。这不是偶然波动，是结构性下滑，需要从流量质量和用户体验两个维度同时入手。

首页→列表页看似损失最多（绝对值），但 PIE 矩阵告诉我们，详情页→购物车的损失才是真正的高优先级（高 Impact + 高 Ease）。

![流失瀑布](output/charts/04_loss_waterfall.png)

## 心路历程：这个项目是怎么做出来的

### 起点：从"做一个漏斗图"到"做一个完整的分析"

最初的想法很简单——画一个电商漏斗图。但开始动手后，很快就遇到了第一个问题：**真实的用户行为不是线性的**。大量用户从广告直接跳到详情页，根本不经过首页和列表页。如果按传统的 Home→PLP→PDP→Cart→Checkout 严格路径，95% 以上的流量都会被当作"无效流量"丢弃。

这个发现让我意识到：**方法论的选型本身就是分析的一部分**。于是引入了"宽松漏斗"和"严格漏斗"双模型，各自回答不同的问题。

### 第二个转折：数据不够真实怎么办？

这是一个模拟数据集。模拟数据的最大问题是：所有渠道、所有国家的转化率几乎一样（差异只有 1-2 个百分点）。真实电商中，不同渠道的转化率可能差 3-5 倍。

要做两个决定：
1. **要不要用它？** —— 用。数据分析师的日常就是面对不完美的数据，关键不是数据有多好，而是你能从里面挖出什么。
2. **怎么处理它的局限？** —— 所有结论都标注"基于模拟数据"，不做虚假承诺。面试中展示"知道自己不知道什么"比假装数据完美更成熟。

### 第三个挑战：统计分析太多了怎么办？

多维度下钻分析时，同时跑了十几组 t 检验。如果不用 Bonferroni 校正，几乎所有 p 值都 <0.001——不是因为真的都有差异，而是因为样本量太大（63 万会话）。这是一个经典陷阱：**大样本下统计显著 ≠ 实际有意义**。

解决方案：t 检验只告诉你"是否有差异"，Cohen's d 告诉你"差异有多大"，Bonferroni 保证你不会把随机波动当成发现。三种方法各有角色，缺一不可。

### 第四个问题：算出损失然后呢？

很多分析停留在"这个环节流失了 ¥933 万"。但业务方会问：**所以呢？你告诉我先改哪个？要花多少钱？改了能回本吗？**

这就是 PIE 矩阵和 What-If 模拟要回答的问题。不是因为详情页损失最惨重就优先改它，而是因为它同时满足三个条件：(1) 损失大、(2) 改动成本低（加购按钮固定底栏、社会证明等前端改动）、(3) 有明确的度量指标。给出策略不是分析的终点，给出**带 ROI 估算的策略才是**。

### 最大的教训

**"交叉到达率"不能叫"转化率"。** 这是我在写文档时才彻底想清楚的一点。宽松漏斗中各页面的数据是"同时到达了 A 和 B 的会话占到达 A 的比例"，这描述的是重叠关系，不是因果关系。叫"转化率"会让读者误以为用户在按顺序往下走，但实际上大量用户是跳过首页直接命中详情页的。命名不只是文字游戏——它影响读者对结论的理解。

## 分析框架

### 为什么选择"双漏斗"模型？

真实电商中，大量用户通过广告、搜索、社媒直达商品详情页（深链），而非按首页→列表页→详情页的线性路径浏览。单一的严格路径漏斗会将 95.8% 的 PDP 流量标记为"未进入漏斗"，严重低估流量价值。

| 模型 | 用途 | 关键指标 |
| :--- | :--- | :--- |
| **页面覆盖分析**（宽松漏斗） | 评估各页面独立触达能力，发现深链流量分布 | 交叉到达率 |
| **严格路径漏斗** | 评估理想路径的端到端留存，发现流程断裂点 | 顺序转化率 |

### 六阶段分析闭环

```
数据探查 → 漏斗建模 → 多维诊断 → 流失根因 → 损失量化 → 策略闭环
```

| 阶段 | 核心工作 | 产出 |
| :--- | :--- | :--- |
| **1. 数据探查** | 五表加载、字段标准化、关联完整性校验、数据质量报告 | 数据概览与质量评估 |
| **2. 数据清洗** | 会话时长异常值处理、漏斗宽表构建（633,450 行） | `funnel_wide.csv` |
| **3. 漏斗建模** | 页面漏斗 ×2 + 行为漏斗 + 5 渠道专属漏斗 + 品类漏斗 | 9 种漏斗视图 |
| **4. 多维诊断** | 渠道/设备/国家/品类/忠诚度/获客渠道 × 时段/趋势/交叉 | 20+ 维度分析 |
| **5. 流失根因** | t 检验 + Cohen's d + Bonferroni 校正 + 渠道×环节流失矩阵 | 统计显著性报告 |
| **6. 损失量化** | PIE 优先级矩阵 + 退款损失 + 广告 ROAS + What-If 模拟 | 策略摘要 + 基准快照 |

## 统计学方法

分析方法的选择均有明确理由，避免"为用而用"：

| 方法 | 应用场景 | 为什么用它 |
| :--- | :--- | :--- |
| **独立样本 t 检验** | 流失 vs 转化用户行为差异 | 二分类结果变量的均值比较 |
| **Cohen's d** | 效应量评估 | 大样本下 p 值几乎总是显著，需要效应量判断实际差异大小 |
| **Bonferroni 校正** | 多维度同时检验 | 控制 Family-Wise Error Rate，避免多重比较的假阳性 |
| **卡方检验** | 渠道×转化关联性 | 检验分类变量间独立性 |
| **PIE 矩阵** | 优化优先级排序 | Impact × Ease 双维度评估，确保资源投向回报最高的方向 |

## 数据说明

本项目使用**算法生成的模拟电商数据**（非真实用户日志），涵盖 2021-2023 三年数据：

| 表 | 行数 | 说明 |
| :--- | ---: | :--- |
| `events.csv` | 2,000,000 | 用户行为事件流（浏览/点击/加购/购买） |
| `transactions.csv` | 103,127 | 交易订单（含退款） |
| `customers.csv` | 100,000 | 用户画像（忠诚度/获客渠道） |
| `products.csv` | 2,000 | 商品信息 |
| `campaigns.csv` | 50 | 广告活动 |

> **局限说明**：模拟数据中各渠道/国家/品类的转化率差异较小（~1-2pp），真实电商中差异通常更显著。分析结论用于方法论演示，不可直接作为商业决策依据。
